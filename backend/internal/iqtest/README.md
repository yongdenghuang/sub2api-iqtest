# 账号页的智商测试

账号管理页提供以下入口，全部使用 `/admin/iqtest` 的真实记录：

- 勾选账号后点击 **批量智商测试**，每个选中账号依次执行糖果和鹈鹕骑自行车 SVG 测试。默认使用 GPT-6 Astra（`gpt-6-astra`）和服务器内置题目，不创建定时计划。账号间默认并发 3 个。
- 页面显示任务编号、已完成测试项数、通过 / 质量失败 / 请求异常 / 跳过数量。任务在后台执行，同一浏览器标签页刷新后恢复进度；“运行记录”可查询历史批次。
- “查看结果”支持分页，每条记录可打开其真实输出，SVG 项可预览对应图片。
- 所有糖果 / SVG 检查在模型留空时使用 GPT-6 Astra；新计划预填此模型，显式填写其他模型仍可覆盖默认值。
- 顶部 **测试计划** 进入智商测试页的“测试计划”标签，可创建或编辑定时计划。

请求失败不会自动重新提交批次。若提示无法确认提交，请先检查运行记录，避免重复消耗额度。不可用账号由现有执行器记录跳过原因；模型请求错误与答案质量失败分别处理。

## 统计与筛选

统计栏覆盖所有未删除账号，不受搜索、分组或当前分页影响。每个账号仅归入一个类别，按两项测试各自最近一次结果判断，优先级如下：

1. 任何一项最近结果为 `quality_fail` → 质量异常。
2. 否则，任何一项为 `infra_error` → 请求异常。
3. 否则，至少一项为 `pass` → 质量正常。
4. 无结果，或仅有跳过结果 → 尚未测试 / 已跳过。

这与基于连续失败策略的历史标记是不同的指标。账号列表“智商状态”列仍只依据最近一次糖果测试判断正常 / 降智。

质量筛选使用 `iq_quality=quality_fail|infra_error|normal|untested`，数据库在计数和分页之前应用，支持与平台、分组等条件组合。全选筛选结果、批量编辑、导出和上游倍率快照均传递此条件。

`GET /api/v1/admin/iqtest/summary` 返回全局分类计数；`GET /api/v1/admin/iqtest/runs/:id` 在运行中返回已保存结果的实时计数。接口沿用管理员认证。

质量标记不自动改变账号启用状态。现有上游 403 / 429 等运行状态处理仍由原执行流程负责。

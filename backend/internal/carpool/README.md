# 拼车订阅额度同步

后台入口：`/admin/carpool`。默认关闭，按分组单独启用。适用于绑定一个 OpenAI OAuth 主账号的 OpenAI 订阅分组；同一个上游不能同时启用两个池。有效人数取当前已开始、未到期、未停用的订阅和用户，包含车主自己的有效订阅。

## 分配方式

- **手动额度**：设置每人每周美元上限，保存后立即生效，不需要上游查询成功。不会清零已用金额或移动周期。后台只查询官方用量，不会按人数或官方百分比覆盖上限。分组 `weekly_limit_usd` 是唯一额度来源，原生分组管理修改也会生效。建议直接登录 Codex 使用账号、或自行管理重置卡的车主采用此模式。
- **动态均分**：由管理员主动选择，按下面的采样规则自动测算。已有自动池升级后保持原模式；新的管理页配置默认选择手动。由手动切回动态时清除旧估值，从初始总额度重新采样，不复用受站外消费影响的旧估算。模式切换本身不重置使用记录。
- 每分钟调用现有的官方用量查询，读取 5 小时和 7 天窗口（额度调整只依据 7 天窗口），不调用重置卡领取/消耗接口。
- 官方百分比并不等于固定美元额度。使用两个实时样本之间的上游消耗和本地成本增量估算总量，至少跨 2 分钟、5 个百分点、1 美元。整数百分比增加一个百分点余量；连续估值取均值。未积累足够样本时使用管理员设置的初始总周额度。
- 采样成本包含此上游的全部本地流量，按拼车分组基础倍率归一化；其他分组消耗也会减少官方可用份额。直接在本站以外使用上游、模型组合变化、用户特殊倍率、异步日志延迟等都会影响估值，应查看实际用量，不把估值当作官方承诺额度。
- 首次采样从初始总额起步；后续重置或用量比例变化触发重新采样时，会保留最近容量作为暂用值，直至有足够新样本。车友页面因此标注“当前已生效额度”，不把重新采样说成再次使用管理员初始额度。
- 有效成员共享相同周上限。上限按可用总量求解，使所有成员的 `max(周上限 - 已用, 0)` 之和不超过估算剩余额度。有人已超出降低后的上限时，不把其已经花掉的部分重新发给其他人。退出/到期用户的已用量在初始采样阶段也不退回池中。
- 只写分组 `weekly_limit_usd` 和该分组有效订阅的周窗口/周用量；不修改钱包、历史请求、授权信息、订阅有效期、已有日/月用量及窗口。未初始化的日/月窗口随首次周初始化补齐。

## 官方重置

“同步官方重置”是独立开关，两种额度模式都可使用。开启时执行以下确认流程；关闭时仍展示官方用量和倒计时，但不修改本站订阅周窗口/用量，恢复原有本地按周维护。未使用的重置卡不会计入美元额度，也不会自动消耗。关闭整个拼车功能同样保留最后周上限，恢复原有本地按周规则。

重置时间前移到新周期，并且旧周期已经结束或用量比例明显回落时，需要间隔至少 45 秒的两次一致查询才确认。5 小时窗口不会清零周用量。仅百分比下降、时间没推进时重新采样，不重置订阅用量。5 分钟内的时间漂移保留原锚点。

确认后，新起点为官方重置时间减去 7 天。从当前计数中减去日志可证明的旧周期消费，保留已经入账的新周期消费；日志缺失时保守保留不明消费。不会通过重新汇总覆盖整个计数，避免漏掉尚未写入日志的请求。重复查询同一周期不会重复清零。

启用官方重置同步的订阅不会仅因本地时钟到期而自动发放新周额度；等待官方确认。读数无效、账号异常、绑定变化或无人订阅时保留当前额度并显示原因。管理员显式手工重置订阅仍按原有功能执行。

## 同组更换上游

分组换成另一个单独的 OpenAI OAuth 主账号后，自动调整暂停，管理页显示旧、新账号。点击“保存设置”或“立即同步”会先询问是否覆盖绑定；取消保持额度绑定不变。确认只接受弹窗中明确的旧、新账号编号，期间再次换账号或重复提交旧确认会返回 409，必须刷新后重新确认。无需重建分组、订阅或 API Key。

确认后以一个事务覆盖拼车额度绑定并记录 `upstream_replaced` 事件，保留旧配置、官方窗口与采样状态供核查。清除旧账号的估算、重置候选和错误，重新读取新账号。手动模式采用确认时的每人周上限；动态模式从确认时的初始总额度重新采样。原有“一账号仅启用一个池”限制继续生效，冲突时整笔事务回滚。

切换不清零车友已用额度，也不移动订阅周起点；首次同步和同一官方周期内的后续同步都保留计数。启用同步官方重置时，等待新账号**下一次**官方重置按两次查询确认后，再按原有日志扣除规则更新周用量，避免把换账号当成领取新额度。未启用同步时继续采用本站周重置规则。不改钱包、历史账单、账号凭据或订阅有效期。

## 运维与验证

独立 `carpool_groups` / `carpool_events` 表保存配置、采样状态和调整记录。进程间分组互斥，数据库事务锁定订阅计数后更新；提交后失效 API Key 中的分组缓存和订阅缓存。每次成功轮询重试缓存失效。配置、同步和事件接口仅管理员可访问，接入现有审计中间件。

`TOKEN_REFRESH_ENABLED=false` 的部署验证进程不启动后台轮询。主进程默认仍需管理员启用一个池后才进行查询/额度调整。单机每分钟刷新启用列表，多实例配置传播最多延迟一分钟。

## 官方监控卡片

登录后的“渠道状态”(`/monitor`) 保留官方 V1 用量条、官方重置倒计时、探活延迟、近 60 次检测和可用率。管理员需将监控关联到本车的上游账号，开启“探活 + 配额”，并在系统设置开启用户端配额展示；探活 Key 应只路由到对应上游，避免探测与配额来自不同车辆。监控 `group_name` 仅作显示，不授予权限。

用户端列表和详情均按登录身份过滤：只有当前生效、未停用/删除的订阅及用户，才能看对应订阅组所绑定账号的监控。过期、未开始或退订立即失去访问，直接请求其他监控详情返回 404。未关联账号和已停用的卡片不对普通用户展示；管理员可看全部。此权限独立于动态均分开关，固定额度车同样适用。成员查询失败或依赖未初始化时拒绝返回数据，响应禁止缓存。

## 车友展示

拼车详情只在左侧“我的拼车”(`/carpool`) 独立页面展示；仪表盘和我的订阅保留原有布局，不插入拼车卡片。前端每 30 秒读取本地最新快照，后台保持每分钟查询官方；隐藏标签页暂停请求。刷新页面不会消费重置卡或触发额外上游调用。

只读 `GET /api/v1/carpool` 使用现有 JWT、后台模式访问限制和面板限流。服务器从登录身份确定用户，仅返回该用户当前生效、启用拼车额度的订阅（手动和动态均支持）。订阅/用户到期、停用、删除、尚未开始，或池停用后，不再返回本车。访问判断、个人用量和本车汇总使用同一只读可重复读事务。响应禁止缓存；成员明细仅返回当前登录者，其他成员的昵称、编号、个人分配及用量不会进入响应。本车总额、总已用、剩余和人数仍提供共享汇总。不包含邮箱、上游账号、凭据、其他车的数据、钱包或原始错误。

- 本车本周总额度 = 当前已生效周上限 × 生效人数；已用 = 本车有效成员周用量之和。
- 车友页明确标注“手动额度 / 动态均分”：手动显示“手动设定总额度”（例如 4 人 × 600 = 2400）；动态显示“当前动态分配总额”，取后台已经执行的分配结果，而非把官方百分比当作美元余额。变更模式或额度随页面轮询同步。手动不展示估算容量或采样提示，两种模式均独立说明重置规则。
- 本车剩余 = 所有 `max(分配 - 已用, 0)` 之和。已超额成员不会扣掉他人的可用份额，因此有超额成员时，“总额度 - 已用”可能不同于剩余。
- 用 5 小时、7 天两张卡片展示“我的窗口用量”：请求数、Token 数、账号计费（A）、我的计费（U）。按官方窗口的 `reset_at - duration` 到 `min(now, reset_at)` 汇总，左闭右开；只计算当前登录用户、当前拼车分组、对应上游账号和有效订阅匹配的本站日志，排除其他车友、监控探测及站外直接使用。
- Token 包含输入、输出、缓存写入和缓存读取。A 使用原生公式 `COALESCE(account_stats_cost,total_cost) * COALESCE(account_rate_multiplier,1)`，U 使用 `actual_cost`。两项均仅汇总当前用户；不使用整车费用冒充个人消费，也不以个人费用除以整车百分比推算总量。
- 每张卡片单独标明“官方共享用量 · 整辆车”，展示该窗口的官方比例、起点及重置倒计时。两种口径不混算。官方窗口缺失或已到期时，个人统计与原生 Codex 统计一致，改查最近 5 小时/7 天，并明确标注“最近时段 · 本站记录”；官方比例及重置时间仍以实际读数为准，不伪造 0 或借用另一窗口。有效比例缺少重置时间时保留比例，不推断官方起止时间。旧版本快照保留已有的 7 天官方数据，待后台同步补齐 5 小时官方读数。
- 动态模式另展示估算整周上游容量；手动模式仍显示管理员设置的总额。删除车友名单及用户页底部的长篇额度模式说明，保留模式标签、重置规则和同步时间。
- 首次查询前显示未知值。同步失败、超过 3 分钟未更新、重置未确认或人数待调整时显示明确状态；倒计时到零不会自行清零已用额度。

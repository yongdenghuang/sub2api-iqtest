# 拼车订阅额度同步

后台入口：`/admin/carpool`。默认关闭，按分组单独启用。适用于绑定一个 OpenAI OAuth 主账号的 OpenAI 订阅分组；同一个上游不能同时启用两个池。有效人数取当前已开始、未到期、未停用的订阅和用户，包含车主自己的有效订阅。

## 分配方式

- 每分钟调用现有的官方用量查询，只读取 7 天窗口，不调用重置卡领取/消耗接口。
- 官方百分比并不等于固定美元额度。使用两个实时样本之间的上游消耗和本地成本增量估算总量，至少跨 2 分钟、5 个百分点、1 美元。整数百分比增加一个百分点余量；连续估值取均值。未积累足够样本时使用管理员设置的初始总周额度。
- 采样成本包含此上游的全部本地流量，按拼车分组基础倍率归一化；其他分组消耗也会减少官方可用份额。直接在本站以外使用上游、模型组合变化、用户特殊倍率、异步日志延迟等都会影响估值，应查看实际用量，不把估值当作官方承诺额度。
- 有效成员共享相同周上限。上限按可用总量求解，使所有成员的 `max(周上限 - 已用, 0)` 之和不超过估算剩余额度。有人已超出降低后的上限时，不把其已经花掉的部分重新发给其他人。退出/到期用户的已用量在初始采样阶段也不退回池中。
- 只写分组 `weekly_limit_usd` 和该分组有效订阅的周窗口/周用量；不修改钱包、历史请求、授权信息、订阅有效期、已有日/月用量及窗口。未初始化的日/月窗口随首次周初始化补齐。

## 官方重置

重置时间前移到新周期，并且旧周期已经结束或用量比例明显回落时，需要间隔至少 45 秒的两次一致查询才确认。5 小时窗口不会清零周用量。仅百分比下降、时间没推进时重新采样，不重置订阅用量。5 分钟内的时间漂移保留原锚点。

确认后，新起点为官方重置时间减去 7 天。从当前计数中减去日志可证明的旧周期消费，保留已经入账的新周期消费；日志缺失时保守保留不明消费。不会通过重新汇总覆盖整个计数，避免漏掉尚未写入日志的请求。重复查询同一周期不会重复清零。

启用池的订阅不会仅因本地时钟到期而自动发放新周额度；等待官方确认。读数无效、账号异常、绑定变化或无人订阅时保留当前额度并显示原因。管理员显式手工重置订阅仍按原有功能执行。停用同步会保留最后的周上限并恢复原有滚动周规则。

## 运维与验证

独立 `carpool_groups` / `carpool_events` 表保存配置、采样状态和调整记录。进程间分组互斥，数据库事务锁定订阅计数后更新；提交后失效 API Key 中的分组缓存和订阅缓存。每次成功轮询重试缓存失效。只有管理员可访问接口，接入现有审计中间件。

`TOKEN_REFRESH_ENABLED=false` 的部署验证进程不启动后台轮询。主进程默认仍需管理员启用一个池后才进行查询/额度调整。单机每分钟刷新启用列表，多实例配置传播最多延迟一分钟。

测试：`go test -tags=unit ./internal/carpool ./internal/service -run 'Carpool|ResetRequires|OnlyFreshWeekly|PercentageDrop|NaturalResetAnd|CapacityUses|EqualCaps'`；真实 PostgreSQL 集成测试 `go test -tags=integration ./internal/carpool`；前端 `pnpm exec vitest run src/views/admin/__tests__/CarpoolView.spec.ts`。
